# 终端命令审批与路径边界设计

## 目标

为桌面端受治理终端建立不可由普通输入、粘贴或回车绕过的高风险命令审批闭环。命令由 Electron 主进程裁决，Renderer 仅负责展示中文确认界面；批准、拒绝和拦截均写入 Runtime 审计记录。

## 方案

终端默认采用“整行提交”模式。Renderer 的文本输入框和 ANSI 终端视图都不得直接调用 PTY 的原始 `write` 接口。Renderer 通过受限 preload API 传入一条不含换行符的命令；主进程解析并执行如下流程：

1. 拒绝空命令、控制字符、多行输入、命令串联、管道、重定向、变量展开和其他 Shell 元字符。
2. 对可解析的单一命令进行词法拆分，并验证显式路径参数始终位于该会话的项目根目录内。
3. 仅允许只读安全白名单中的命令免确认；删除、格式化、强制推送、硬重置、危险进程终止、远程脚本执行及所有未列入白名单的命令均识别为高风险，生成稳定的命令摘要和影响范围，且不向 PTY 写入。
4. 只有可信用户在 Renderer 的中文确认界面批准同一审批标识后，主进程才向 PTY 写入该完整命令和回车。
5. 非高风险命令通过同一个主进程入口写入 PTY。被拒绝、过期、重复提交或不匹配的审批标识均不能执行命令。

该策略故意不支持任意 Shell 元编程或全屏交互式程序。它以受治理的工程命令为边界，优先保证单条命令的可审计性和项目路径约束；需要更宽松的交互能力必须另行设计具备 OS 级隔离的受限执行器，不能绕过当前策略。

## 审计

Electron 主进程使用本地 Runtime API 新增的终端命令决策端点写入审计。审计详情只保存脱敏后的命令摘要、风险等级、影响范围和最终决定，不保存凭据文本。Runtime 负责验证会话属于 Run、Actor 为受信任人工且请求时间有效。

## 测试

- Desktop 单元测试验证：多行/元字符绕过被阻止、项目外路径被阻止、高风险命令先请求确认、批准后只执行一次、拒绝后不执行。
- Runtime 与 API 测试验证：合法 Run 会话的审计记录、非可信 Actor 和不存在会话被拒绝、审计详情脱敏。
- Renderer 测试验证：高风险命令显示中文确认框；批准或拒绝调用正确 preload API；普通命令直接提交；ANSI 终端不具有直接 stdin 写入通路。
