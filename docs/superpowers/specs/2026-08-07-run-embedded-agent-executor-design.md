# Run 内嵌 Agent 执行器设计

## 背景

当前 Run 详情页存在三个关联问题：

- 进度图所在左列被右侧长控制轨撑高，固定高度的流程图下方产生大片空白。
- Run 页只能启动 Agent 和跳转到终端模块，缺少 Run 内执行器。
- 终端模块加载的是 Agent 持久化输出，但没有绑定启动 Agent 时创建的桌面 PTY，因此无法输入，并与 App 中的 Agent 轮询形成重复状态源。

## 模块边界

### Run 模块

Run 模块是运行编排与 Agent Job 操作中心，负责：

- 展示工作流进度和当前节点。
- 启动当前 Agent 节点的 Job。
- 在 Run 页面内查看、切换和操作该 Run 的多个 Agent Job。
- 为交互式 Job 提供输入、中断、尺寸同步和停止能力。
- 为自动执行 Job 提供只读实时日志。

Agent 的全屏视图仍属于 Run 路由，不进入独立终端模块。路由固定为：

```text
#/runs/{runId}/agents/{jobId}
```

### 终端模块

终端模块是项目或工作区级的独立终端工作台。它不依赖 Run，也不要求先启动 Agent，负责：

- 独立创建 Shell、Codex CLI 和 Claude CLI 会话。
- 选择项目工作区或 worktree。
- 输入命令、调整尺寸、停止和重启会话。
- 查看终端历史和导出 Evidence。

Run 执行器与终端模块可以复用 `TerminalViewport` 和桌面 PTY 桥接能力，但不共享 UI 路由或业务生命周期。

## 页面布局

桌面端继续使用约 65/35 的主区：

- 左列改为纵向工作区，上方为紧凑流程图，下方为 Agent 执行器。
- 流程图高度控制在 `320px` 到 `460px`，不再随右侧控制轨拉伸。
- Agent 执行器占用流程图下方空间，消除无意义空白。
- 右列保留当前节点、Runtime 授权操作、Agent 启动表单和下一节点信息。
- Run 资源标签仍位于主区下方。

响应式规则：

- `980px` 以下按流程图、执行器、控制轨顺序堆叠。
- `620px` 以下 Job 标签允许横向滚动，操作按钮保持可触达且不溢出。

## 多 Job 执行器

执行器顶部使用 Job 标签：

- 标签显示短 Job ID、Provider 和稳定状态。
- 默认选择最新的活动 Job；没有活动 Job 时选择最近更新的 Job。
- 启动新 Job 后自动选中对应标签，但不改变页面路由。
- 标签切换只切换输出和输入目标，不创建或重启 PTY。
- 活动 Job 可以停止；已结束 Job 保留只读输出。

执行器空状态应明确提示当前 Run 尚未启动 Agent，不保留大面积空白画布。

## 状态与数据流

`App` 是 Run Agent 会话的唯一状态所有者：

1. Run 页面提交 Agent 启动请求。
2. `App` 创建 Runtime Agent Job；交互模式下继续创建桌面 PTY，并完成 Runtime 会话绑定。
3. `App` 保存 Job、PTY binding、实时输出和持久化输出。
4. Run 内嵌执行器通过 props 接收 Job、输出、可写状态和操作回调。
5. 输入、`Ctrl+C`、resize 和停止操作由 `App` 转发到对应 PTY。
6. Runtime 轮询只负责权威 Job 状态和持久化输出；PTY 读取只负责实时终端数据。

Run 页面不再维护独立的 Agent Job 副本，也不再启动第二套轮询。界面使用 Job ID 合并实时输出与持久化输出，避免重复事件和状态抖动。

终端模块维护自己的独立终端会话，不读取或接管 Run Agent binding。

## 路由行为

- 点击“启动 Agent”后保持当前 Run 详情路由。
- 新 Job 自动成为内嵌执行器的活动标签。
- “全屏执行器”进入 Run 子路由，不进入 `#/terminal`。
- 主导航“终端”始终进入独立终端工作台。
- 独立终端工作台在没有 Run 上下文时仍可创建终端。

## 错误处理

- PTY 创建失败：将 Runtime Job 标记为可恢复失败，并在 Run 执行器内显示错误。
- PTY binding 丢失：Job 保留只读输出，明确提示交互会话已断开。
- 输出持久化达到上限：实时终端继续工作，界面显示持久化受限状态。
- Runtime 轮询失败：保留最后一次权威状态，不在多个状态之间来回切换。
- 自动执行 Job 永远不显示为可写。

## 测试范围

组件测试覆盖：

- 启动 Agent 后不改变 Run 路由。
- 新 Job 自动选中。
- 多 Job 标签切换输出和输入目标。
- 交互式 Job 输入、`Ctrl+C`、resize 和停止回调。
- 自动执行和失去 binding 的 Job 为只读。
- Run 页面不再链接到独立终端模块。
- 独立终端模块无 Run 时仍可创建会话。

应用集成测试覆盖：

- Run 执行器与 `App` 中 PTY binding 使用同一个 Job ID。
- 状态轮询不会创建 Run 页面本地副本。
- Run Agent 全屏路由保持输入能力。

视觉验收覆盖：

- 桌面主区无大片无功能空白。
- 流程图、执行器和控制轨无重叠或横向溢出。
- `980px` 和 `620px` 断点下顺序正确、标签可滚动。

## 非目标

- 不修改 Runtime Agent 协议和桌面 PTY API。
- 不把独立终端模块改造成 Run Agent 管理页。
- 不在本次修复中增加跨 Run Agent 汇总视图。
- 不自动恢复应用重启前已丢失的本地 PTY 进程。
