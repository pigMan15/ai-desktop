# 全功能本地交付工作流设计

## 目标

为项目 `G:\Project\ai\demo` 安装一条可立即创建 Run 的“全功能软件交付演练”工作流。部署仅使用 `local-staging` 本地演练环境，不连接真实服务器。

## 流程

工作流采用单路径顺序执行，包含需求登记、需求分析、技术设计、方案审批、开发实现、构建证据、自动测试、质量门禁、发布审批、本地部署、验收证据、发布报告和复合收尾。它覆盖 `task`、`agent`、`approval`、`gate`、`evidence`、`deploy`、`report`、`composite` 全部节点类型。

Agent 节点绑定现有公共角色的不可变版本。需要产物的节点声明固定路径，使用 Run 页面“扫描并提交所需产物”完成登记。审批与门禁保持人工操作，部署节点记录本地 staging 结果。

## 安装方式

安装脚本通过 `WorkflowDefinition` 和编译器校验定义，再调用 `WorkflowRuntimeService.create_workflow` 与 `bind_project_workflow`。脚本使用固定工作流 ID，重复执行时复用已有资产和当前版本，并重新确认项目绑定。

## 验证

- 编译诊断必须为空。
- 数据库中存在工作流资产、当前版本和目标项目绑定。
- 绑定版本的定义包含 13 个节点、12 条边、7 个角色快照和 1 个质量门禁。
- 使用指南覆盖 Run、Agent、终端、产物、审批、门禁、部署、审计、恢复和知识库。
