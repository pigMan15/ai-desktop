# Run 产物扫描反馈设计

## 背景

Run 页面可以扫描当前节点声明的产物，但原界面只在页面顶部显示一条短提示。用户无法快速确认本次提交了多少产物、哪些产物仍然缺失，以及 Runtime 是否已经允许完成当前节点。

## 目标

- 在产物操作附近持续展示最近一次扫描结果。
- 区分本次新提交、已存在且未变化、缺失和无效四类结果。
- 明确告诉用户当前是否可以执行“完成当前节点”。
- 保持扫描与完成为两个独立的显式操作，不自动完成节点。

## 交互设计

扫描完成后，在“Runtime 授权操作”区域内显示“产物检查结果”状态区。状态区展示：

- `已满足 X/Y`，其中满足数量为 `registered + unchanged`，总数为四类结果数量之和。
- `本次提交 N`、`已存在 N`、`缺失 N`、`无效 N`。
- 缺失产物 ID，以及无效产物 ID 和失败原因。
- 最近一次扫描对应的当前节点。

当最近一次扫描没有缺失或无效产物，并且最新 Run projection 已包含当前节点的 `NODE_COMPLETED` 授权动作时，状态区显示“产物要求已满足，可以完成当前节点”，并加强该完成按钮的视觉优先级。

当 Runtime 尚未授权 `NODE_COMPLETED` 时，状态区显示“暂不能进入下一步”，并优先展示 projection 中当前节点的阻塞原因。前端不根据产物计数自行授权完成操作。

扫描请求失败时，错误显示在同一状态区。成功扫描结果在切换当前节点或发起新的扫描前保持可见，避免刷新后反馈消失。

## 数据与状态

`RunDetailPage` 保存最近一次成功的 `NodeArtifactScan` 及对应节点 ID。扫描成功后：

1. 保存完整扫描结果，而不只保存 projection。
2. 使用返回的 projection 立即更新界面。
3. 刷新完整 Run overview。
4. 使用刷新后的 `allowedActions` 和 `blockingReasons` 判断并展示下一步状态。

扫描结果只用于解释 Runtime 状态，不作为权限来源。是否显示或启用“完成当前节点”仍完全由 Runtime 的 `allowedActions` 决定。

## 展示位置

状态区位于“Runtime 授权操作”标题和授权动作列表之间，与扫描和完成按钮处于同一视觉区域。完整产物记录仍通过 Run 资源栏中的“产物”入口查看。

桌面和移动端均采用自然换行的紧凑信息带，不新增嵌套卡片或弹窗。

## 测试范围

- 新提交和已存在产物正确计入“已满足”。
- 缺失和无效产物显示 ID 与无效原因。
- Runtime 授权 `NODE_COMPLETED` 时显示“可以完成当前节点”。
- Runtime 未授权完成时显示“暂不能进入下一步”和阻塞原因。
- 扫描与完成保持为两个独立操作，扫描成功不会自动执行完成动作。
- 切换节点时不会把上一节点的扫描结果显示在新节点上。

## 非目标

- 不修改 Runtime 的产物扫描协议或授权规则。
- 不自动执行“完成当前节点”。
- 不在本次改动中重做独立“产物”页面。
- 不从前端产物计数推断节点已经满足完成条件。
