# 复杂业务研发知识库（虚构示例）

> 本仓库所有名称、系统与流程均为虚构，仅用于演示知识组织与 Agent 更新方法。
> 维护角色：`example-team`；示例日期：2026-08-05。

## 仓库目的与适用场景

本知识库演示一个订单履约系统团队如何沉淀可被 AI Coding 消费的领域知识：
需求澄清、方案设计、编码、问题排查、Code Review 与发布计划都能先读知识库，
再回到代码核对实现事实。

## 知识分层

| 层级 | 目录 | 可信级别 |
| --- | --- | --- |
| 全局领域 | `main/` | 团队正式结论 |
| 应用 | `applications/` | 每个应用一个子目录 |
| 候选知识 | `candidate/` | 未确认，仅作输入 |
| 个人经验 | `personal/` | 个人记录，不是正式事实 |
| 模板 | `template/` | 新建知识时复制 |

## 正式、候选与个人知识的区别

- 正式知识：经过人工审核，带来源证据、Owner 和失效条件。
- 候选知识：置信度不足，只能进入 `candidate/`。
- 个人经验：不构成团队正式结论，引用时必须重新验证。

## 人工审核与知识回补

变更索引、路由、规则和模板必须人工审核。Agent 只提出提案，
由人工确认后写入；写入后可从 Run 产物回补新知识。

## 当前代码仍是实现事实

本仓库是对当前实现的理解记录，不是替代实现。任何易变信息
（API、模型、消息）都只提供定位入口，改代码前必须核对当前代码。
